# Benchmark 契约

## 分层

| 层级 | 当前状态 | 目标 |
| --- | --- | --- |
| 工程正确性 | 已实现自动测试 | 增删改、事务回滚、隔离、预算、版本、MCP 协议 |
| 合成开发集 | 已实现 smoke-v1，30 题 | 可复现的词法检索基线、回归与失败分析 |
| 真实知识库开发集 | 待用户真实查询积累 | Obsidian 的状态、术语、跨笔记与真实问题 |
| 独立测试集 | 待建立 | 在调参之外判断泛化效果 |
| 规模与并发 | 待建立 | 文档数量/长度、冷暖缓存、并发、内存和索引吞吐 |
| Agent 完整回答 | 待建立 | 工具调用、事实忠实、引用支撑、无答案处理和总 token |

smoke-v1 包含：精确词 5、换说法 5、中英混合 3、多证据 3、状态 3、范围 5、无答案 6。
全部是可公开的人工演示资料与标签，不构成独立盲测集。类别占比也不代表真实使用频率。
状态题显式传入筛选条件，只验证过滤能力，不代表 Agent 已学会自动识别历史与现状。

## 标签和质量指标

每题保存 id、category、query、kb_ids（可选）、filters（可选）、relevant。
relevant 中每份所需文档标记 doc_id 和一段原文 contains；空列表表示资料不能回答。
运行前校验文档、原文引句、范围与元数据条件相符。必须看到返回片段包含引句才算命中。

- Recall@k：前 k 个片段中可见的所需证据文档数 / 所需证据文档总数；重复文档只计一次。
- Hit@k：有答案的问题中是否至少找到一份所需证据。
- MRR@k：第一份可见相关证据的排名倒数。
- nDCG@k：二元证据相关性的排名质量，重复文档无额外增益。
- Precision@k：命中证据文档数 / k；不足 k 个结果不缩小分母。
- empty_on_unanswerable：无答案问题中没有返回候选的比例；**不是模型拒答率或正确率**。
- empty_on_answerable：有答案问题中没有候选的比例；越低越好。
- kb_leakage：每题返回范围外结果的数量，平均值必须为零。

有答案/无答案指标分别统计，空标签不能给 Recall 或 nDCG 贡献虚假的满分。
目前每份文档每题只标一个必需片段，不支持多种等价证据方案或语义裁判；未来要升级标签版本与计分版本。
当一句引文被分块跨开，严格评测会判未命中；这是当前可见证据契约的限制，需结合失败样例判断。

## 性能与开销

记录搜索调用外层时间（包括本地 trace 写入、不含 MCP 传输）、p50/p95，以及 load_filter/tokenize/rank/pack 分阶段时间。
默认每题预热 1 次、测量 5 次，题序固定种子打乱；质量按确定性输出计一次。
阶段时间不含最终 trace 写入，因此不能直接相加等同外层耗时。
首次索引单独记录扫描、读取哈希、解析、存储、删除旧资料的耗时、文件数、字节数和片段数。
正文字符数与完整检索结果 canonical JSON 的 UTF-8 字节数分开记录；字节数不含 MCP 封装。
未使用模型，没有模型 usage 或费用；不能将字符数换算成已节省 token 的结论。

小演示库的几毫秒差异容易受操作系统与缓存影响。正式性能实验要求：

1. 固定硬件、系统、Python、依赖、数据快照与后台负载；记录变更。
2. 用代表性的文档长度和 100 / 1000 / 10000 文档工作负载，避免只有重复短文档。
3. 至少 5 组交错 A/B 运行；分别测冷启动和暖查询，记录原始样本和内存。
4. 新增服务级负载工具后再报告 MCP 端到端延迟、吞吐和并发。
5. 同时报质量与开销，不以减少返回结果换取隐含的“提速”。

## 可复现与对比规则

报告记录 dataset_hash、corpus_hash、逐文件版本、config_hash、代码文件哈希、Git 状态、依赖版本、系统信息与检索设置。
uv.lock 随代码保存。报告、问题快照和 traces 写入唯一目录；临时评测索引不会覆盖日常索引。
代码指纹覆盖 src、pyproject.toml 和 uv.lock；即使尚无 Git 提交，也可识别被测实现。
数据快照由来源清单和内容哈希标识；私有语料不复制进报告，复现实验还需保留对应原始版本。

compare 拒绝数据集、语料、计分版本、top_k、正文预算或测量次数不一致的直接对比。
分块大小、检索策略等实验自变量允许变化并显示在各自报告中。若要比较不同预算，应另建预算消融实验，不能冒充等预算提升。
每次输出指标差值、逐题变化和配对 bootstrap Recall 差值区间。小开发集区间只描述样本，不证明统计泛化。
环境变化会提示性能结论不可控；操作者仍需检查后台负载和缓存。compare 不会自动批准采用改动。

报告完整保存本次题目与标签，所有原始运行目录和基线档案默认忽略；真实数据集放在 `.local/` 或 `benchmarks/private/`。
只有 `benchmarks/datasets/smoke-v1.jsonl` 是批准公开的 JSONL 数据集；其他 JSONL 默认不提交。
公开实验使用 `scripts/export_benchmark_summary.py` 导出到 `benchmarks/public/`：先验证问题集与语料均为公开演示内容，
仅输出聚合指标、参数和代码指纹，移除逐题记录、文档身份、引文、来源清单、trace 与本机环境详情。
详见 [隐私与公开发布](privacy.md)。

## 修改采用标准

硬约束测试全部通过、来源范围不泄漏。声明改善的主指标必须有对照数据；其余指标与逐题退化全部披露。
首次基线不设凭空的“90% 达标”门槛。真实开发集建立后再为产品目标设阈值。
参数调优只能用开发集；独立测试集冻结后用于阶段验收。增补样例需升数据集版本并重跑两侧。

参考：[Ragas 指标分类](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/)。本项目当前使用可审计的确定性证据匹配，不依赖 LLM 裁判。
