# EXP-0001：简单词项匹配与 BM25 的初始对照

- 日期：2026-10-07（Asia/Shanghai）
- 状态：completed
- 目的：建立测量流程并观察排序差异，不以此证明通用检索质量。
- 假设：相对于匹配词项数量，BM25 的词频与长度归一化可能改善相关证据的排序。
- 变化因素：`strategy=overlap` → `strategy=bm25`。
- 固定条件：smoke-v1、12 篇相同文档、相同切块、top_k=5、正文预算 4000 字符、预热 1 次、重复 5 次、固定随机题序。
- 运行顺序：overlap 后 bm25，各一轮；不构成受控性能优化结论。

| Recall@5 | 0.958333 | 0.958333 | 没有新增召回 |

| nDCG@5 | 0.922122 | 0.927577 | +0.005455 |
| 无答案题无候选比例 | 4/6 | 4/6 | 证据充分性问题未解决 |
| 范围外返回数 | 0 | 0 | 本开发集未发生范围泄漏 |
| 进程内搜索 p95（ms） | 1.847135 | 1.695505 | 仅记录观察，不声称提速 |

| 平均响应 JSON 字节 | 1340.333 | 1369.233 | 略有增加，不能当作 token |

逐题质量变化只有 q07：首次相关证据排名从第三变为第二。
没有召回下降的题目，但一次小样本开发集运行不能证明不存在其他退化。
配对 bootstrap 的 Recall 差值区间为 [0, 0]，因为两种策略对所有题目的 Recall 完全一致。

BM25 阶段 p50：加载与过滤 0.901 ms、分词 0.261 ms、打分 0.018 ms、打包 0.026 ms。
可以据此提出“加载与重复分词是否值得缓存”的假设；当前数据量很小，尚不足以决定优先优化它。

## 失败案例

- q10「切成小段会不会失去前后文」：答案在 chunking.md，但关键词交集不足，两个策略都未返回证据。
- q28「Orion 上线后有多少付费用户」：资料只有未立项的创意，没有用户数量；检索仍返回同主题候选。
- q29「Embedding 模型价格是多少」：资料介绍原理，没有价格；检索仍返回相关片段。

后两题说明“检索有结果”和“有证据能回答”是不同的判断。当前接口返回 candidates_found，不表示答案已获支持。

## 决定与边界

BM25 保持首版默认策略，overlap 作为简单对照保留。此选择是工程起点，不是证明其普遍优于其他策略。
继续建立真实问题集，再评估语义检索；不针对 q10 增加手写同义词来粉饰演示集分数。
证据充分性需要独立设计与评测，不能直接把 BM25 分数当作置信度设一个通用阈值。
