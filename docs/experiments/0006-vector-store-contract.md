# EXP-0006：Qdrant 向量存储契约

- 日期：2026-10-10
- 状态：completed（V1 local/memory）；Server 部署未验收。
- 阶段：V1；验证真实向量数据库的工程行为，不评估语义检索。
- 目标：维度/模型契约可核验，写入幂等，过滤在排名前生效，更新/删除有效，重启后数据一致。
- 方法：固定3维单位测试向量、隔离知识库与索引代次；使用Qdrant持久化local模式运行，不改现有个人索引。
- 主要指标：场景通过数、入库/查询/重开/更新/删除操作耗时、实际点数、错误拦截。
- 硬约束：错误向量不得部分写入；模型/代次不能混用；过滤不能漏出范围；正文不写入payload或trace。
- 回归：同条件smoke-v1 BM25报告对比；原始报告只保存本地。
- 限制：固定向量不能证明语义收益；local模式不能代替Qdrant Server的多进程/部署验证。

## 结果

依赖：可选 `vector` extra，Qdrant client 1.19.1/Python 3.12.14，uv.lock 固定。
存储规格、来源版本、generation 共同决定 collection 与 named vector；UUID点身份固定，重复写入覆盖同一身份。
不兼容 schema 明确拒绝，不重建或覆盖；来源版本变化应建立新契约。

`knowledge-rag vector-check` 使用 `fixed-3d-v1`，三个点、alpha/beta 两个合成范围。
每次独立本地目录，完整 trace、manifest 与不可覆盖报告保留于 `.state/`；失败报告也保留。
报告包含 fixture、代码和契约指纹、依赖版本、精确检索设置、操作/错误数、阶段耗时及磁盘占用。

| 验收项 | 结果 |
| --- | ---: |
| 固定向量验收 | 18/18 |
| 全项目自动测试 | 50/50 |
| 操作 trace 数 | 23 |
| 预期错误拦截 | 4 |
| 最终有效点数 | 2（从3点删除1点） |
| 隔离目录文件大小合计 | 12,952 bytes |
| local 搜索操作 p50/p95 | 0.945 / 1.125 ms（6次，场景各异） |
| upsert 操作 p50/p95 | 240.228 / 340.608 ms（3次，含持久化） |

重启后计数与查询一致；全局最近点属于 beta 时，alpha top-1 仍正确返回 alpha，
状态过滤能选出本来排名靠后的候选。错误批次全部验证后才写入，没有因无效向量产生部分写入。
后端故障的批次原子性不在此保证内，候选代次与失败发布保护在 V3 实现。
自动测试另验证错误 schema、payload 来源损坏、来源/模型/代次隔离、目录跨进程锁及不可覆盖 manifest。

性能值只描述单次微型工程验收：成功操作样本用于分位数，预期错误单独计数，
操作计时不含 trace 文件追加；总时长还包含首次 SDK 导入、打开/关闭库与验收逻辑。
并未固定 CPU/负载或做规模测试，不能据此判断生产吞吐、ANN 或优化收益。
