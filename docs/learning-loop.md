# 学习经验回流

## 一个问题如何成为知识

问题与对话 → 可复现的问题记录 → 假设 → 实验 → 结果 → 学习笔记 → 核对 → 索引。

当前提供模板和协作约定，不自动抓取历史聊天，也不把对话全部当作事实入库。
默认先在忽略的 `.local/learning/` 记录项目学习，之后可将该目录作为 knowledge-rag-mcp 的独立来源。
`docs/learning/` 只保留模板与人工审阅后的公开技术笔记；真实问题、对话摘录、个人信息与原始引文留在本地。
要同步进 Obsidian 时使用正常 Markdown 和相对链接，保留原始来源与实验编号。

## 每次总结至少记录

- 问题是什么、如何复现、当时的环境。
- 原先的理解或假设，与实际观察分开。
- 做了什么实验，报告、代码版本和来源在哪里。
- 结论是什么、在哪些条件下成立、还有什么未验证。
- 下一步是什么；哪些结论替代了旧笔记。

总结可以短，但必须能追溯。模板中的 `status` 为 draft/reviewed/verified/superseded，
`kind` 为 learning/experiment/decision；个人事实不应从技术学习笔记中自动推导。
一次自动测试通过只能验证相应工程行为，不能把整篇含推测的笔记标记为全部已验证。

## 对话协作方式

用户遇到问题后，把问题、观察或代码现象发来；在解决时同步维护项目实验与状态记录。
完成一个学习主题后整理一篇笔记，用户可校正理解。真正进入个人知识库的内容应具有明确来源和核对状态。
后续检索优先读取已核对的记录；涉及过往结论时显示日期、实验范围和失效条件。
