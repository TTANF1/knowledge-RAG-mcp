# 演进路线

## M0：可测量的检索基线（当前）

两个演示知识库、三个 MCP 只读工具、增量索引、词法检索、30 题开发集、trace、对照报告和学习模板。
验收为工程测试与实际 MCP 握手、调用通过；明确保留召回和无答案失败，不把检索命中包装成回答准确率。

## M1：真实资料与真实问题

选择 Obsidian 中适合接入的目录，形成独立本地配置。建立约 30–50 道真实查询，人工标明来源、状态和缺失信息。
按主题与资料来源分开开发集和保留测试集，避免同一问题的轻微改写跨集合泄漏。
加入扫描更新任务、中文术语词典实验、明确当前状态查询与“索引新鲜度”。每项变化均留下对照报告。

## M2：语义检索与混合检索

当前进入规划，详见 [向量索引构建计划](vector-index-plan.md) 与 [EXP-0005](experiments/0005-vector-baseline-plan.md)。
使用独立Embedding/VectorStore接口，推荐Qdrant本地服务；local模式用于隔离测试。
学习 Embedding、相似度与向量索引；按存储契约、真实编码、版本化构建、dense评测逐步交付。
固定模型版本、输入文本、维度、批量大小；记录向量化耗时、输入 token（如有）、费用（如有）和缓存命中。
比较 BM25 / 向量 / 融合，重点看换说法问题收益和准确标识符问题的退化。

## M3：证据选择与上下文

评估重排、父子片段、去重和预算分配。使用固定主 Agent 模型的实际 token 计数，比较质量与上下文开销。
区分检索无候选和候选不足以回答，增加证据充分性判断与独立评测。

## M4：Agent 与知识回流

固定 Agent、模型、提示词和工具版本，建立端到端问题集；记录是否检索、工具轮数、来源引用和事实忠实度。
把复现问题、实验结论和学习笔记作为可追溯的知识来源；增加 reviewed/verified 状态与来源关系。
只有真实使用有需求时才增加多来源聚合、远程 MCP、授权、任务队列或图谱检索。
